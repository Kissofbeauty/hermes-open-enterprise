# Contributing to Hermes Open Enterprise

Thanks for helping! This project is a public template — please keep it free of any real organization data.
By participating you agree to the [Code of Conduct](CODE_OF_CONDUCT.md).

## Branch model

```
main  ←  uat  ←  feature/<name>
```

- `feature/<name>` — your work (e.g. `feature/egress-ipv6`, `feature/docs-admin-guide-en`). Branch from `uat`.
- `uat` — integration; tested on a dev stage before promotion.
- `main` — released, protected. Changes reach `main` only by pull request from `uat`.

Open your pull request against **`uat`**.

## Commit messages

[Conventional Commits](https://www.conventionalcommits.org):

```
feat(ohermes): add --dry-run to rm
fix(egress): keep previous rules when squid -k parse fails
docs(readme): clarify production requirements
```

Types: `feat` `fix` `docs` `refactor` `test` `chore` `ci` `security`. Use `!` or a `BREAKING CHANGE:` footer for
breaking changes (e.g. a changed `.env` variable or folder layout).

## Conventions

- Code, comments, the README and the guides in `guides/` are in English.
- LF line endings everywhere (see `.gitattributes`). On Windows, set `git config core.autocrlf false`.
- Shell scripts (`ohermes`, `Infrastructure/**/*.sh`) must stay executable and pass `shellcheck -S warning`.
- Pin every container image to `tag@sha256:digest`; update only after testing on a dev stage.
- Never edit `docker-compose.override.yml` by hand — it is generated by `ohermes sync`.
- Keep changes lean: smallest change that solves the problem, no speculative options.

## Running the tests

```bash
# 1. Shell lint (same list as CI)
shellcheck -S warning ohermes Infrastructure/ops/scripts/*.sh Infrastructure/hermes/start.sh \
  Infrastructure/hermes/tests/live-check.sh Infrastructure/egress/start.sh Infrastructure/deploy/deploy.sh

# 2. Python syntax
python3 -m py_compile Infrastructure/hermes/setup.py Infrastructure/hermes/model_capture.py

# 3. org-guard unit tests (host Python 3, or inside the pinned Hermes image)
python3 -m unittest discover -s Infrastructure/hermes/plugins/org-guard/tests -v
docker run --rm --network none -v "$PWD/Infrastructure/hermes/plugins/org-guard:/g:ro" \
  --entrypoint /opt/hermes/.venv/bin/python "$HERMES_IMAGE" -m unittest discover -s /g/tests

# 4. Config validation
cp .env.example .env && docker compose config --quiet
./ohermes check && ./ohermes reconf --dry-run

# 5. Live hardening check against a running employee container (dev stage)
docker compose up -d
./ohermes create -e test.user@example.com -s test
Infrastructure/hermes/tests/live-check.sh test-user
```

CI (`.github/workflows/ci.yml`) runs steps 1–4 plus Caddy and Squid config validation on every pull request.

## Pull request checklist

- [ ] Targets `uat` from a `feature/<name>` branch; title follows Conventional Commits
- [ ] **No secrets or real data**: no `.env`, API keys, tokens, passwords/hashes, real names, emails, domains
      or internal IPs (use `example.com`, `john-doe`, `10.213.x.x`). Run `git diff --cached` and a secret scan
      (e.g. `gitleaks detect` or `git secrets --scan`) before pushing
- [ ] Nothing from `Users/` (except `_template/`), `Archive/`, `Logs/`, `Backups/` or generated files
- [ ] shellcheck, org-guard unit tests and `docker compose config` pass
- [ ] Security-relevant change? Updated `SECURITY.md` / tests, and ran `live-check.sh` on a dev stage
- [ ] Docs updated (README, `guides/`, `CHANGELOG.md` under *Unreleased*)

## Reporting bugs and security issues

- Bugs and feature requests: GitHub Issues (templates provided).
- **Security vulnerabilities: do not open a public issue** — see [SECURITY.md](SECURITY.md).
